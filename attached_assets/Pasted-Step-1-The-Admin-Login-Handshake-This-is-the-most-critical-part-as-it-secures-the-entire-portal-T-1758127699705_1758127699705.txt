Step 1: The Admin Login Handshake
This is the most critical part, as it secures the entire portal. The goal is to get a token from the server that proves the user is an administrator and then save that token on the browser.

Frontend Action: The admin.html page needs a simple login form with two input fields for email and password, and a submit button. When the user clicks "Log In," a JavaScript function should:

Collect the email and password from the form.

Use a fetch request to send this data to a new backend endpoint, for example, /login-admin.

If the request is successful, the server will send back a JSON Web Token (JWT).

The JavaScript must then securely store this token in the browser, using localStorage.setItem('adminToken', token).

Backend Action: Your server.js needs a new POST /login-admin endpoint. This route will:

Receive the email and password from the frontend.

Find the administrator in your database using their email.

Use bcrypt.compare to check if the provided password matches the hashed password in the database.

If the credentials are valid, it will use jwt.sign to create a new token, containing the administrator's ID and role.

Finally, it will send this token back to the frontend in a JSON response.

Once this handshake is complete, every other administrative action will be dependent on this stored token.

Step 2: Dynamic Dashboard Data
Now that you have a token, you can unlock the rest of the portal. The dashboard data should not be hardcoded.

Backend Action: You will create a new GET /admin/dashboard-data endpoint. This route must be protected by your existing authAdmin middleware. Inside this function, you will:

Use Mongoose to run a series of countDocuments() queries on your Student, Teacher, QuizQuestion, and WorkFile collections.

You will also need to query for content that is pending, using countDocuments({ isApproved: false }) on your relevant models.

Gather all these counts into a single JSON object (e.g., { totalStudents, totalTeachers, ... }).

Send this JSON object back to the frontend.

Frontend Action: Your admin.html needs a JavaScript function that runs as soon as the page loads (or immediately after a successful login). This function will:

Retrieve the adminToken from localStorage.

Use fetch to call your new GET /admin/dashboard-data endpoint.

Crucially, you must include the token in the request headers: headers: { 'Authorization': Bearer ${token} }.

When the response comes back, parse the JSON data.

Use document.querySelector to find the HTML elements for each metric (e.g., the span for total students) and update their innerText with the new data from the server.

By following these professional steps, you will have a secure, data-driven, and fully integrated administrator portal.
